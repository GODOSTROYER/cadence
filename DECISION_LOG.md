# Decision log

Fifteen decisions for the revised submission. The original 18 decisions are preserved in `docs/DECISION_LOG_historical.md`. Measured results live in `REPORT.md`; expected gains below are hypotheses.

1. **Record both annotation and human review provenance.** Codex initially labelled all 200 new examples with individual rationales before predictions. Arnav Bule subsequently completed human review of all 200 examples, confirmed on 16 September 2026. See [review record](docs/HUMAN_REVIEW.md). Measured judge–human agreement remains unavailable.
2. **Preserve historical results.** Fixes changed the pipeline; overwriting old predictions would disconnect the headline from its code. Historical manifests and replay remain separate from revised experiments.
3. **Lock before inference.** Sample IDs, label hashes, policy threshold and source fingerprints are frozen. Fixing an infrastructure failure is recorded separately; tuning prompts against the new errors would consume the holdout.
4. **Keep BM25 for now.** Warm local retrieval is already sub-millisecond. Hybrid/reranking needs relevance and usable-resolution labels before it can justify added models, memory and maintenance.
5. **Keep one model call for now.** Decide-before-retrieve may reduce anchoring, but adds a call and router failure modes. Run paired dev experiments before adopting it; no untested architecture is called optimal.
6. **Separate intent confidence from risk claims.** The model's confidence is a coarse self-report. The original 0.9 threshold missed its dev recall constraint and was selected by an F2 fallback. Report that honestly and freeze the operating point.
7. **Enforce policy on secondary sensitive intents too.** A benign primary intent should not override an explicitly predicted billing/security issue. Deterministic rules still have precedence and can only add escalations.
8. **Add a release veto after drafting.** Citation membership, URLs, placeholders, missing resources and certain promises are checked. Rejected drafts become holding replies and escalations; this sacrifices coverage and is not a semantic grounding proof. After the frozen run exposed false action claims and obsolete limits, general guards were repaired; the separate cache-only replay is explicitly retrospective, not new generalization evidence.
9. **Use three verified canonical procedures.** Broadly filling missing links from guesses risks adding unsupported instructions. A narrow versioned mapping is easier to inspect and maintain.
10. **Use a controlled no-evidence ablation.** The old zero-shot baseline changed both prompt and policy. New k0/k6 variants keep those fixed. Compare pre-guard drafts too, because a citation-required k0 release automatically fails the grounding gate.
11. **Judge both presentation orders.** Normalize signatures equally and show each candidate's own evidence. Publish order inconsistency, keep weak results, and do not call same-family model scores human validation.
12. **Make replay explicit.** The fast offline command verifies and recomputes archived artifacts. It does not run the changed agent, simulate model latency or prove live deployment performance.
13. **Bound requests and separate visitor data from evaluation caches.** Deployment uses per-process concurrency limits, request deadlines, sanitized errors and no response persistence. This is suitable demo hardening, not distributed abuse protection.
14. **Treat keys as credentials and quotas as project-level.** Keys remain in environment variables even though plaintext was permitted. Rotation does not multiply quota for keys in the same project; a free-tier flag cannot verify billing.
15. **Spend submission effort on inspectable evidence.** Repaired test isolation, source/label manifests, actual free-tier receipts, readable failure examples and a concise report have higher immediate value than fine-tuning, autonomous account actions or infrastructure expansion.
